# Web Authentication Brute-Forcer with Anti-CSRF Token Bypass (PoC)

This repository contains an automated Proof of Concept (PoC) credential brute-forcing script designed to audit web authentication forms. The tool features an integrated **dynamic CSRF (Cross-Site Request Forgery) token extraction engine**, enabling it to simulate password auditing attacks on modern, token-protected administrative web interfaces (such as DVWA or custom login forms) during authorized penetration testing.

---

## 🔬 Vulnerability Analysis & Technical Mechanics

Standard brute-force tools fail when targeting modern login forms because the server expects a unique, cryptographically secure anti-CSRF token with every single login attempt. This script automates a sophisticated multi-step authentication traversal loop to bypass this defensive control:

1. **Stateful Session Tracking (`requests.Session`)**: The script instantiates an HTTP session object to hold and track browser cookies automatically across subsequent requests. This is mandatory, as the CSRF token generated by the server is explicitly tied to the current cookie state.
2. **Dynamic Anti-CSRF Token Parsing (`extract_csrf_token`)**: Before submitting a password guess, the script makes a proactive `GET` request to the authentication page. It runs a pre-compiled case-insensitive Regular Expression (RegEx) matrix searching for common hidden input structures:
   - `name="user_token" value="..."`
   - `value="..." name="csrf"`
3. **Automated Payload Generation**: If a token is successfully parsed, the script dynamically injects it into the `POST` payload dictionary along with the current password candidate from the dictionary file.
4. **Multi-Vector Response Triage**: The tool evaluates authentication success or failure based on standard post-exploitation web indicators:
   - Behavioral analysis mapping textual response signatures (`failed`, `incorrect`).
   - Status code metrics handling traditional `200 OK` logic shifts or `302 Found` server dashboard relocations.

## 🚀 Configuration & Deployment

1. Prepare your password dictionary file (e.g., `passwords.txt` or standard wordlists like `rockyou.txt`) and place it inside the workspace. If no file is detected, the script automatically generates a small testing sample file upon initial launch.

2. Open the script file and update the default target attributes inside the `__main__` entry point:
```python
URL = "http://<TARGET-ENDPOINT-OR-LOCAL-LAB>/login.php"
```

3. Launch the credential audit via your terminal environment:
```bash
python formbruteforcer.py
```

### Telemetry Logs:
The console displays verbose logs for every individual password attempt, printing the active token values in real-time, and will drop a clean visual matrix onto the screen as soon as a correct credential combination is successfully intercepted.
